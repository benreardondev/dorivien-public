Trust & security

How the current Dorivien demo is designed.

Current public-demo architecture and operating principles.

This page describes the current Dorivien public demo, not a certification or guarantee. Client deployments can require additional controls depending on the business, integrations, data involved, and contractual requirements.

Current demo controls

AreaCurrent approach
API secretsDesigned to stay on the server through environment variables. The browser does not need the OpenAI API key.
Conversation storageThe current demo does not use an application database for conversation history. The browser keeps the active demo conversation in memory while the page is open.
Model requestsWhen live AI is enabled, the server sends the conversation context required to generate the response. The current OpenAI request is configured with store: false.
Business rulesProduction business rules are designed to be configured server-side. Customer messages and browser parameters do not get to redefine the approved business profile.
Lead handoffAn optional client-approved webhook can receive complete leads or safety escalations. Webhook payloads can be HMAC-signed and include a stable event ID for deduplication.
Input limitsMessage length and request-body limits are enforced server-side.
Abuse controlsThe public response endpoint includes basic per-IP rate limiting.
Browser securityThe server sends content-security, content-type, referrer, permissions, and framing headers. The client widget is intentionally allowed to be framed by a client website.
SafetyA deterministic safety layer checks for gas, carbon monoxide, smoke, fire, flames, sparks, and related immediate concerns before an ordinary service reply is returned.

Production expectations

A real client deployment should be configured around that business's approved data, tested with representative scenarios, given the minimum integrations it needs, and reviewed whenever business rules change.

Reporting an issue

Until a dedicated security mailbox is created, use the booking/contact path on the main website and clearly label the issue as a security concern. A dedicated security@dorivien.com address should be created after the domain and branded email are active.
